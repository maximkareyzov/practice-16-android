# Практическая работа 16.1–16.6

Учебное Android-приложение на Java: список пользователей и просмотр/редактирование профиля.

## Что реализовано

- `ListView` с собственным `BaseAdapter`, модель `User` и демонстрационные пользователи.
- В портретной ориентации профиль открывается поверх списка, в горизонтальной — справа от списка.
- Индикаторы подключения: 0 — офлайн (серый), 1 — онлайн (зелёный), 2 — отошёл (красный).
- Редактирование имени, возраста и текстового статуса в `UserActivity`; кнопки возврата и сохранения.
- Обновление списка и профиля после редактирования, общие стили и `Transform.parseIntOrDefault`.

Данные хранятся в статическом списке, как в задании: изменения действуют до завершения процесса приложения, не сохраняются на диск. Статус подключения — демонстрационное поле, а не проверка сети.

## Запуск

1. Открыть папку проекта в Android Studio, установить Android SDK Platform 35 и JDK 17.
2. Дождаться Gradle Sync и запустить `app` на устройстве или эмуляторе Android 6.0 (API 23) и выше.
3. Выбрать пользователя, нажать значок карандаша, изменить данные и сохранить. Повернуть устройство для проверки горизонтальной разметки.

Для сборки из терминала: `bash gradlew assembleDebug` (при установленном Android SDK и заданном `ANDROID_HOME`). Тест преобразования строки: `javac -encoding UTF-8 -d /tmp/practice16-test app/src/main/java/com/example/practice16/Transform.java tests/TransformTest.java && java -cp /tmp/practice16-test TransformTest`.


## Практика 17.1–17.6

Добавлены экран входа и регистрации с TabHost, Firebase Authentication и Realtime Database, проверка заполнения с анимацией и вибрацией, сохранение логина в SharedPreferences, восстановление сессии Firebase, экран загрузки с анимированным фрагментом и звуком. Кнопка «Открыть список без входа» оставлена для предыдущей практики.

### Подключение Firebase

1. В `app/google-services.json` уже добавлена конфигурация учебного проекта Firebase для `com.example.practice16`. Чтобы использовать собственный проект, замените этот файл конфигурацией своего Android-приложения.
2. В Authentication включите способ Email/Password. Создайте Realtime Database и установите правила, разрешающие авторизованному пользователю чтение и запись **только своего профиля**:

```json
{ "rules": { "UsersProfileInfo": { "$uid": { ".read": "auth != null && auth.uid === $uid", ".write": "auth != null && auth.uid === $uid" } } } }
```

3. Убедитесь, что Email/Password и правила базы настроены в проекте Firebase, к которому относится конфигурация. Синхронизируйте Gradle в Android Studio и запустите приложение на устройстве с сетью. Старый список можно открыть без входа.
4. Введите email либо учебный логин без @ (для Firebase он преобразуется в адрес вида `логин@practice17.invalid`). Пароль должен соответствовать требованиям Firebase, обычно не менее 6 символов.

**Отличия от методички по безопасности:** пароли не хранятся открытым текстом в Realtime Database или SharedPreferences; авторизацию, уникальность и восстановление сессии обеспечивает Firebase Authentication. В Realtime Database хранится `UsersProfileInfo/<uid>` с именем, возрастом и статусом. Сохранённый логин — только подсказка; пароль повторно не подставляется. Не включайте общедоступные правила чтения/записи и не используйте настоящие пароли для тестов.

Если Firebase возвращает ошибку записи профиля, вход отменяется. Учётная запись Firebase Auth уже может остаться созданной: удалите её в консоли проекта перед повторной регистрацией или вручную создайте профиль по UID после настройки правил. При входе приложение считывает профиль из Realtime Database и добавляет его в список практики 16 рядом с демонстрационными данными. Редактирование списка пока действует только в памяти и не записывается обратно в Firebase.
